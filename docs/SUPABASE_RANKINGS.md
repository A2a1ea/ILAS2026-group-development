# Supabase Rankings Setup

The game server can store shared rankings in Supabase when these server-side environment variables are set:

```env
SUPABASE_URL=https://your-project-ref.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
SUPABASE_RANKING_TABLE=rankings
```

Do not put `SUPABASE_SERVICE_ROLE_KEY` in browser-side code. Set it only in the server host environment, such as Render environment variables.

## Create the table

Open Supabase SQL Editor and run:

```sql
create table if not exists public.rankings (
  id bigint generated by default as identity primary key,
  name text not null,
  stages integer not null check (stages >= 1),
  score integer not null check (score >= 0),
  used_letters jsonb not null default '[]'::jsonb,
  comment text not null default '',
  created_at timestamptz not null default now()
);

create index if not exists rankings_order_idx
  on public.rankings (stages desc, score desc, created_at desc);

alter table public.rankings enable row level security;
```

The game server uses the service role key, so it can read and write this table even with RLS enabled.

## Render

In Render, add these environment variables to the game web service:

```env
SUPABASE_URL=https://your-project-ref.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
SUPABASE_RANKING_TABLE=rankings
```

Then redeploy. The browser still calls the local game endpoint:

```text
/api/rankings/stages
```

The server forwards rankings to Supabase when the Supabase variables are present. If Supabase is not configured or unavailable, it falls back to `.logs/rankings.json`.
